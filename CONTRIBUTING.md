# Contributing to The Nightshift Ghouls

## Branching (trunk-based)
- `main` is the trunk and is protected; it is always releasable and is what GitHub Pages serves.
- Work on short-lived branches: `feat/<slug>` for features, `fix/<slug>` for fixes, `docs/<slug>`, `chore/<slug>`.
- Branches live hours to days, not weeks. Rebase on `main` before opening a PR.

## Commits
Use [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`, `ci:`.
Add a `Signed-off-by:` line (`git commit -s`) to certify the [Developer Certificate of Origin](https://developercertificate.org/).

## Pull requests
1. Run `make setup` once to install the git hooks.
2. Run `make lint test build` locally; CI runs `make lint test` on every PR.
3. Fill in the PR template and add a line under `[Unreleased]` in `CHANGELOG.md`.
4. A human reviewer from `CODEOWNERS` approves; PRs are squash-merged.

## Ground rules
- No secrets, credentials, personal data or private hostnames in commits (see `PRIVACY.md`).
- `RELEASE_MANIFEST.json` and `SHA256SUMS` are generated by `make release`; never edit them by hand.
